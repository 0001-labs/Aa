# Aa

> **Read first:** `/Users/joachim/.agents/harness-instructions.md` (harness instructions), `/Users/joachim/0001/AGENTS.md` (0001). This file wins where they differ.

Aa is the text editor of 0001's products: Ezo's notes and writing blocks, Link's comments and messages, and whatever comes next. It is Markdown drawn as you write it, Notion's architecture on 0001's own terms. Public at https://github.com/0001-labs/Aa (`origin`, `main` pushed with its tags), linked at the foot of the playground.

## What it is

- **The document is Markdown.** That is what every product stores, what the `.ezo` file is, what agents write and what the iPhone app reads, so nothing is converted and nothing is lost. `src/markdown.ts` reads a text into blocks (paragraph, heading, bullet with or without a box, quote, fenced code, divider) and a block into runs (text, syntax, line break), every character kept with its offset.
- **One editable element a block**, as Notion does it, never one big contenteditable. Each block is drawn from its source and read back from the screen after each change (`src/render.ts`); the blocks it touched are read again, so `- ` typed at the start of a paragraph makes a bullet and a heading that loses its `## ` is a paragraph (`replaceRange` in `src/document.ts`).
- **Edit formatted text, store Markdown.** No Markdown syntax is shown, while writing either: a heading is its size, never its `#` (Backspace at its start makes it a paragraph, and an empty heading says "Heading 2" until it has words). Typed Markdown shortcuts transform into formatting. Markdown has no underline or colour, so those two are written as Notion writes them: `<u>words</u>` (⌘U) and `<span color="red">words</span>`, in one of `TEXT_COLORS` (gray, red, orange, green, blue, purple), each a dark ink of Design system 1's palette on light paper and a light one on dark (`--aa-color-<name>` to change one); Text colour on the bar opens them, Default taking the colour off. Bullets and checkboxes remain visible while their text is edited. The toolbar and keyboard shortcuts format without writing syntax; links use a URL field. Source characters stay in DOM spans for lossless reading and source-offset mapping.
- **The browser types, Aa decides.** Typing, spelling and IME composition are the browser's (nothing is touched while composing). Enter, Shift-Enter, Backspace at a block's edge, Delete at its end, paste, cut, ⌘B/I/E/K and ⌘⇧X, undo and the caret's way between blocks are Aa's (`src/editor.ts`). Undo is a stack of whole documents (`src/history.ts`): letters typed within a moment are one step, deleting is a step apart from typing, a space after a word begins a new one, and undo puts the caret where the change it took back was. A `value` set from outside draws again only the blocks that changed, so a collaborator's edit keeps the caret and focus.
- **`<aa-editor>`** is the element (`src/element.ts`, `defineAaEditor()`): `value` is the Markdown, `input` fires on each change, `readonly` and `placeholder` are attributes. `createEditor(host, options)` is the same without an element. Light DOM, so the page's rules reach it.
- **Drawn as Design system 1's prose.** `src/aa.css` draws every block as Design system 1's `prose.css` draws the same Markdown read on a page (`data-ds-prose`), so writing in Aa and reading it elsewhere look the same: a line a square, a square between blocks and two before a heading, a title 20px on two squares, `##` and `###` 17px and 15px, code 13px on the same lines in a hairline frame, links underlined in the text's colour, quotes on a muted hairline, a divider that takes no room, tables two squares a row, Design system 1's checkbox, and the Context face for the block menu. The toolbar over selected words is as simple as it can be with a pointer, a grid five squares wide as Notion's: Text colour, Bold, Italic, Underline, Strikethrough, then Link, Code, Equation and Comment, followed by an inert plus-icon cell that completes the five-by-two grid. It is centred over the first selected line with no gap; if it cannot fit above, it stands below the whole selection, clamped to the visual viewport. Each action is named by Design system 1's tooltip with its shortcut (`src/ds1/0-face/tooltips.ts`, copied with Sync 1; the kinds, what the product inserts and a picture are the slash menu's, and touch keeps them on its bar), and where the product answers prompts a row nearest the selected text asks AI about the selected words (under the cells when the toolbar is above the selection, before them when below) (`askAbout`: the words glisten, the answer takes their place as one step to undo and stays selected); its field says Ask in every language, never translated (its screen-reader name is), and focusing it slides the multiline field over the formatting cells within the same panel footprint, using transform motion with a reduced-motion alternative. Enter sends, Shift+Enter adds a line, and composition keeps Enter. Covered formatting buttons are inert until the field closes; it is Design system 1's context bar itself (`.ds-context--bar` from its `context.css`, copied into `src/ds1` with Sync 1's `sheets` export and imported by `aa.css`, which both the package and the Sync 1 copy carry beside it); it stays `role="toolbar"`, opening without the focus. Text colour opens icon-only swatches with accessible names and shared hover/focus tooltips; choosing one closes the palette while the formatting toolbar stays open. Formatting keeps that toolbar open; block-type commands close their command menu. A pointer press outside the formatting toolbar or its open palette dismisses it immediately; the same selection does not reopen it until a new selection is made. Escape leaves editing: Aa clears its native selection, blurs its editable block, closes its controls and removes transient marks without editing content or adding history. It does not leave a blinking caret or immediately reopen controls. IME composition keeps ownership of Escape. Every measure and colour is a `--ds-*` token with its value as the fallback, so a page without the tokens still gets them; a product changes one thing with the `--aa-*` properties (`--aa-heading-gap` for the room before a heading), and its own rules outweigh Aa's. Change a measure in `prose.css` first, then here.
- **Type**: two rules kept here and in Design system 1. **Arrows are always Inter**, in every font Aa sets, code included: "Inter Arrows" (`src/fonts/inter-arrows.woff2`, Inter's arrows alone, limited by `unicode-range`) comes first in each `font-family` in `src/aa.css`, so a new font stack starts with it. **Code is Aa Mono** (`src/fonts/aa-mono.woff2`, Iosevka cut to what code uses), after the product's `--aa-typeface-mono` or `--typeface-mono`, then a system monospace, never a serif. Both fonts ship inside `aa.js` with the styles, and as files in the npm package and the Sync 1 copy (`fonts/`) for an imported `aa.css`, with their licence in `src/fonts/LICENSE.md`.

- **Inline controls** (`src/partials.ts`): documentation opts into `partials: true`. Typing `@button` in prose opens DS1’s state picker; the real `ds-button` is an inline atom, stored as `@Button("Save", "primary")`. Its label and state are edited in DS1’s popover, applied as one undo step. Read-only instances are inert illustrations with an accessible label and state, never app actions. Unknown syntax, code and links remain literal. The playground and documentation examples enable it. Controls are copied with Sync 1, never reimplemented. Selected parts: `editing`, `ds1`, `sharing`, `documentation`, `themes`, `platform-web`. Product data, uploads and account permissions are outside this opt-in documentation feature.

- **Atoms** are pieces of the text drawn as one thing, never letter by letter: a picture, `![name](address)`, out of the box, and whatever a product names (`atoms` in the options: Ezo's mentions, link titles, its own pictures). Each has a `match` that finds it in a line (`atomPattern` makes one from a pattern) and a `draw` that fills the uneditable `.aa-atom` Aa gives it, returning what to stop when it leaves. The text keeps the atom's words, in `data-source`, so it reads back as written; the caret stands beside an atom, and an atom drawn once is kept as the block is drawn again (`src/render.ts`).
- **Asking AI** (a concept, `src/prompt.ts`): with `prompt` in the options, Space in an empty block opens a prompt over it in a live colour (the focus ring's blue), never part of the document; Space again before anything is written listens instead (the browser's speech recognition; the Space may come as the keyboard's `beforeinput` alone, as a phone's does), the words heard set in italics and the caret drawn as a dot while it listens that breathes very slightly the whole time, still or not: a slow pulse of its opacity mixed with the microphone's level, never its size (still with less motion asked for). An empty block with the caret says “Press space for AI or / for commands” where the product answers prompts, “Type / for commands” otherwise. At a sentence's end in a paragraph or a bullet (its . ! or ? and one space, the caret after it with nothing more), and in a bullet with nothing written yet, it says “Press space for AI” after the caret, never the commands, and Space there opens the prompt at the caret: the marker goes into the line, and the answer goes on from there in the same paragraph or bullet. Enter sends it with its section (from the heading over it to the next) as context; the prompt and that section glisten until the answer comes: the accent as a band through the letters alone (a gradient clipped to the text, `data-aa-glisten`), never over the block's box. The whole document goes with the prompt (`document`, `PROMPT_HERE` on its own line where the prompt stands), and the answer is the whole document as it should be afterwards: titles changed, boxes ticked, diagrams written or changed where they stand, new writing at the marker. Aa takes it in, keeping the blocks it left as they were. What it changed is marked (`src/marks.ts`, over the page): a Sharp blue dot after each block changed on its own (a box ticked, a title reworded), a Zenith blue hold round a run it wrote or rewrote (several blocks, a diagram). A dot grows into Design system 1's button, Revert, on hover or focus, by transform and opacity; it puts back that change alone as one step to undo, the caret kept, and is refused once the block has been changed by hand. The words it changed or wrote keep their ink (a decoration layer of their own, `ai`, names them for a product that wants to colour them), and a box it ticked or unticked is ringed in Sharp blue until the marks go. Nothing says what it did beside the marks themselves: Escape puts the marks away (the edits stay) and ⌘Z takes the whole answer back. Marks go when their block is changed by hand, when reverted, on Escape, or when another answer comes. An answer may instead edit in place (`edits`, each an exact passage found once before or after the prompt and what it becomes) and put new writing where the prompt stood (`insert`); Aa applies them as one change, one step to undo, drops the empty block when nothing is inserted, keeps unchanged blocks as they were, and shimmers what changed once. Space on a diagram's board asks the same for the diagram's words written again (`aa-atom-prompt`). The product makes the call: Ezo's `aiPrompt:ask` behind `ezo-ai-prompt`, and `aiPrompt:playground` for the playground.
- **Comments** (`src/comments.ts`, `src/comments-view.ts`), Link's commenting system made a part of the editor, on ranges of the text rather than blocks: a thread is anchored to a run of the Markdown (`from`, `to` and `quote`, the words there) and kept right as the text changes (`mapRange` through the smallest replacement `textChange` finds, the diff collaboration uses, slid back to a word's start where it could stand earlier): an edit before a range moves it, words typed at its end go on with it as a bold word does, an edit inside grows or shrinks it, one over all of it leaves the thread **orphaned**, still listed and no longer marked; a thread from the store whose words are not at its offsets is looked for by its quote nearest to where it was. Moved anchors are given back to the store a moment after the typing (`move`). The commented words wear orange's pastel on the `comments` decoration layer (yellow is highlight's, blue AI's), the open thread's stronger, an unread one's with a line under; the caret coming into them or a press on them opens the thread, Escape closes it and it stays closed until the caret has left. Threads are drawn on Design system 1's squares in a **popover** at the words (16 squares wide, half a square under them, a card on the paper) or in a **panel** the product gives (`panel` on the store: Design system 1's text tabs at its head, Open and Resolved with their counts, the chosen tab listing its threads in the order of the words and marking them in the text): the thread's own row first, with the quote muted in it in a panel (a popover stands right under the words and leaves it out) and Resolve, Reopen and Delete (the creator, after a second press) on the sixteen at its end, a press outside or Escape closing a popover, and arrows up and down in it stepping to the threads before and after when the text has more; each comment's avatar as Design system 1 draws a person (round, one control high, the initial lettered in their ink inside a ring of it), the name in the medium weight, the time relative and muted, the body on 20px lines a square in, the people named in their colour, and under it its reactions as Link has them (`REACTION_EMOJIS`, the sixteen): a chip each with the emoji and its count, pressed where the reader gave it and naming who did, a plus giving one more from the sixteen in the Context face, eight a row, `react` on the store toggling it; "Resolved by Name." on a resolved thread; a composer one square high that grows, Enter sends, Shift-Enter breaks a line, `@` opens the people menu in the Context face, and where the browser can listen the empty field says "Press space to speak, or reply": Space dictates the reply into the field in the prompt's colour (the browser's speech recognition, `dictate` in `src/prompt.ts`), Enter sends what was heard, Escape stops, and any other key stops listening and types on; where it cannot and the product answers prompts, it says "Press space for AI, or reply": Space asks AI about the commented words (the thread so far as its context), what is asked in the prompt's colour, and the answer is the draft to send. Comment in the toolbar and ⌘⇧M start a thread on the selected words. **Aa is a library: the store is the product's** (`comments` in the options, a `CommentStore`: `subscribe`, `me`, `add`, `reply`, `edit`, `resolve`, `remove`, `move`, `seen`, `react`, `people`), with its storage, people, permissions and notifications; `memoryCommentStore` keeps threads in the tab for the playground and tests; `editor.comments` opens, starts and closes from outside. ## Product expansions

Aa is the shared vanilla TypeScript text-editing engine. Caret/focus, native selection, text keyboard behavior, formatting, Markdown, text history and generic extension points belong here. Fix and test those in Aa independently of its consumers. `createEditor` is the framework-independent API; `<aa-editor>` and optional framework adapters wrap it. `editor.dismiss()` leaves editing without changing content or history.

Each product owns its expansion: domain atoms, commands, persistence, permissions and authenticated services. Compose these through Aa's public options and adapters, keeping the copied core unchanged. Document product expansions in their private product/System records; Aa's public documentation covers the shared editor and generic extension API only. Shared geometry and controls belong to Design system 1; shared movement belongs to Drag.

## Plain text

`createPlainEditor(host, { value, readOnly, onChange })` provides one native plain-text block for short specimens and simple writing surfaces. It shares Aa's rounded native-selection painter and inherits the surrounding typography. It has no Markdown conversion, toolbar, menus, atoms or document model; the browser owns multiline input, clipboard, IME and undo. This single-block mode is an intentional exception to the Markdown document/history rules. Use `createEditor` for documents.

With `placeholder` the empty field says it in the muted ink. With `speak`, where the browser can listen, it says "Press space to speak, or …" and Space in the empty field dictates into it as a comment's reply does (`dictate` in `src/prompt.ts`): the words heard written in as they come, the prompt's breathing dot after them and "Listening…" before any, Escape stopping and any other key stopping and typing on. `listening` says whether it is. Team CMS's and Link's Report take it first.

## Releasing to npm

One command publishes a new version, with semantic versioning (`scripts/release.mjs`, the same file in Aa, Design system 1, IDv1, Drag and Worktrees):

- `vp run release patch` — fixes, nothing changes for products (0.2.0 → 0.2.1)
- `vp run release minor` — something new, nothing breaks (0.2.0 → 0.3.0)
- `vp run release major` — something breaks for products (0.2.0 → 1.0.0)
- `vp run release alpha` — a preview under the `alpha` tag (0.2.1-alpha.0, then .1 …)
- `vp run release current` — publishes the version already in `package.json`, for the first release
- `--dry-run` after any of them goes through every step without publishing

It refuses with uncommitted changes or when npm is signed out (`vp pm login`), runs `check`, `test` and `build`, publishes, then commits `Release @0001-labs/aa <version>` and tags `v<version>`. A failed step puts the version back. Products then take it with `vp update @0001-labs/aa`.

## Markdown-backed comments and CLI

`src/comments-markdown.ts` owns the versioned `aa-comments v1` YAML fence and paired HTML anchors. `sourceComments` opts an editor into document-backed threads; existing embedded threads are read automatically. `editor.value` and `onChange` retain comments. Markdown downloads must use `editor.exportMarkdown()` or the DOM-free `exportMarkdown(source)`, which strip live markers and metadata and refuse unreadable comment metadata. Never download `editor.value` directly.

IDv1 account validation and item-code generation are copied through Sync 1 into `src/vendor/idv1`. `src/comments-editor.ts` projects source onto prose while keeping public offsets in the editable source. External source replacement resets local undo. Source comments do not support the optional Yjs text adapter yet, nor anchors inside nested columns/tabs; consumers must use revision-checked saves and enforce authenticated authors/permissions themselves. Existing product-backed stores are not migrated automatically.

After `vp run build`, `node bin/aa.mjs` (installed as `aa`) provides `comments list`, `add`, `reply`, `edit`, `resolve`, `reopen`, `remove`, `export`, and `completion bash`; `--help` lists flags and all operations support `--json`. `AA_AUTHOR` or `--author` supplies a local IDv1 account, not a credential. `--from`/`--to` address UTF-16 offsets in clean Markdown. `export` always strips comments and never overwrites an existing output. CLI checks build the DOM-free entry before running against temporary files.

System selections for this feature: `editing`, `documentation`, `sharing`, `id1`, `platform-cli`, `platform-web`. CLI exceptions: Aa is a local-file library command in its existing package, with no remote API, device sign-in or credential storage. ## Server parsing

`src/parse.ts` and the optional `parse` build export expose the editor’s block/run parser, tables and clean Markdown export without loading DOM components. Server integrations select `entries: ["parse"]` in Sync 1. Product renderers own their output format and must strip source comments with `exportMarkdown` before external export. Build with `vp build --config vite.config.parse.ts`; `tests/parse-entry.test.ts` checks the built entry in a Node process without browser globals.
