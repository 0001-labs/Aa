`@0001-labs/aa/react` holds `AaEditor`, the editor as a React component. React is an optional peer dependency: the core does not import it.

```tsx
import { AaEditor } from '@0001-labs/aa/react'
import '@0001-labs/aa/aa.css'

<AaEditor value={markdown} onChange={setMarkdown} toolbar />
```

These [options](/building/options/) are props: `value`, `onChange`, `readOnly`, `placeholder`, `toolbar`, `menus`, `atoms`, `commands`, `blockCommands`, `onFiles`, `drawEquation`, `correct` and `correcting`. Any other prop goes to the editor's element as an attribute.

Asking AI (`prompt`), comments and `blockPlaceholder` are not passed on by `AaEditor` yet. For those, create the editor yourself with `createEditor` in an effect, as below, or use `<aa-editor>` and its `options`.

## The ref

The ref gives the editor and three methods:

| Member | What it does |
| --- | --- |
| `editor` | The editor itself, or `null` before it is drawn; see [Methods and events](/building/methods/) |
| `focus()` | Puts the caret in the editor |
| `undo()` | Takes back the last step; `true` when there was one |
| `redo()` | Puts it back |

```tsx
const ref = useRef<AaEditorRef>(null)

<AaEditor ref={ref} value={markdown} onChange={setMarkdown} />
<button onClick={() => ref.current?.undo()}>Undo</button>
```

## Keep options stable

Arrays and callbacks that define the editor, `atoms`, `toolbar`, `commands`, `blockCommands`, `menus` and `drawEquation`, should keep their identity between renders: define them outside the component or with `useMemo` and `useCallback`. A new one each render makes the editor again.

## Creating it yourself

```tsx
const host = useRef<HTMLDivElement>(null)

useLayoutEffect(() => {
  const editor = createEditor(host.current!, { value: markdown, toolbar: true, prompt, comments })
  return () => editor.destroy()
}, [])

<div ref={host} />
```
